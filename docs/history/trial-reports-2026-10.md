### 二、被反复点名的四类问题（按出现次数）

1. **静默说谎**（5 次）：空画板判合格、token 工程色相恒 0、31 条越界只列 12 条不说、`nativeShare 66.7%` 与真实 6/6 冲突、note 自称「词表与导出一致」。
2. **两套判定**（3 次）：metrics 用 `>1px`、review 用 `<0` → 1px 越界时结论相反；explore 的 rule 文案与实际 rankKey 不符。
3. **只看局部、不看关系**（3 次）：字阶/留白/色相都是局部属性；主次比算面积不算文字高度；空态只数全页存在性。
4. **参数轴空转**（2 次）：typeScale 等比缩放数学上不改变比值；density 对没有 padding 的页面无效；8 个候选其实只有 3 类改动。

### 三、逐轮修复（只列结构性改动）

| 轮次 | 修复 |
|---|---|
| 1 | 响应预算（32KB→2.2KB）、多工程并行、`addPage` 支持 domain、命令别名与可用类型列表 |
| 2 | 未知属性不再给错误候选、溢出诊断人类可读、页面级 target、宏子节点回写（A5） |
| 3 | 空页 `not-assessable`、token 色相、栅格一本账、锚点单位 ×100 |
| 4 | 对比度兄弟堆叠、结构化锚点配方、探索铺开采样 |
| 5 | containment 硬检查、explore 目标函数含越界惩罚、锚点参照系卫生 |
| 6 | 1px 容差统一（review 改用 metrics 单一来源）、`severity`、`axes` 生效、typeScale 死代码修复 |
| 7 | 导出预算（加性口径）、撑高文字 `stretchedText`、关系约束（主操作/点击区/空态） |
| 8 | 关系层读结构：variant/component 投影、同容器判定并列、空态绑定列表、热区 `hitW/hitH` |

### 四、仍然未解（能力缺口，不是 bug）

| 缺口 | 为什么难 |
|---|---|
| 空洞文案（`vague-centered-hero`） | 属文案语义，几何与参数都碰不到；需要「改写文案 + 换素材」的新能力 |
| type-scale 的多数问题 | 只能动最大正文那一级；真实阶梯问题要改内容层级 |
| 探索的结构轴覆盖面 | 只覆盖「一行多个定宽子项」与「根级堆叠块」；复杂嵌套设计仍无轴 |
| 关系层深度 | 空态已能绑定列表；但「哪个主操作属于哪个区域」仍靠同父判定，没有区域语义 |
| 导出保真 | 静态投影与真实导出仍可能不一致，只能标 `uncertain` 并让用户以报告为准 |

### 五、当前可验证的状态

- `npm test` 17/17；`studio-*` 全过；`macro-lift`、`repeater-where`、`language` 全过
- 一致性契约：`test:studio-consistency` 覆盖「metrics / explore / review 对同一 revision 不得互相矛盾」
- 回退：每轮一个 `_backup/zee-axure-*` 快照 + 最初 tag `rsi-backup-20261027-010431`

### 六、定位声明（第 9 轮试用后确定）

**能当**：几何与可达性 CI 门禁 —— 越界、栅格、热区、空态覆盖、主次失衡、导出预算，且"绿"必须通过 `test:studio-anti-gaming` 的攻击测试。

**不能当**：设计评审签字。L1 是底线，不证明"设计成立"。试用者原话：「这块绿只能证明页面有标题、没有裸露的 20px 按钮」。

### 七、结论（诚实版）

工具现在能稳定回答三类问题：**哪里错了（可定位到节点）、怎么改（具体命令与数值）、离参照系差多少（锚点偏离 + 方向建议）**。

它还回答不了第四类：**怎么更好**。那需要内容层能力（改写文案、换素材、重排信息架构），不是参数与几何能解决的。7.5 分里扣掉的分，基本都在这。

## 2026-10-25 视觉创作反馈复验

对象：v0.2.1 后的工作改动，macOS + Axure RP 9。反馈来自一次六页考研 App 试用；原报告的评分与其旧样本统计属于试用者报告，本页只记录本次独立复验。

### 修复与已有行为

| 反馈 | 本次处理 | 证据范围 |
| --- | --- | --- |
| 单个居中文字向左偏 | 双向居中的 row/column 单 label 继承文字居中；保留显式 left/right | 真实展开、布局和 Axvg 发射定向回归 |
| 字距未计入宽度 | 当前普通 label/按钮自动宽度已计字距；固定宽度仍是约束，补充说明 | COUNTDOWN 带字距测量回归通过；不扩展为所有富文本混排的承诺 |
| hug 面板高度难预期 | 已有规则为全部状态最大高度；写清规则，状态图增加 viewport/content 尺寸 | 260/500px 两状态面板测量为 500px |
| tab-bar 激活态不可定制 | 新增 activeVariant、activeIndicator（none/underline/dot）、justify、itemFlex；接通已有激活/非激活填充、颜色、字号 | 两页范例 check 零警告，原生生成、保存重开及实际导航检查 |
| 静态图初值“剧透” | 说明使用真实变量初值/首状态；交互后场景使用真实预览回放 | 不新增 previewInitial/previewState，也不为截图改动运行时初值含义 |
| fontFamily 与光效 | 明确 RP/1 暂无 fontFamily；给出 Axure/原生富文本改字体路径；光效会作为位图进入原生 | 未实现任意字体的离线与原生一致排版；未声称原生矢量阴影/渐变可编辑 |
| statesSheet 混入进度条态 | 当前拼图已过滤内部 `_fill/s0…s100`；保留诊断用完整 statePreviews | 现有质量回归通过，文档说明两个输出字段区别 |
| fillx180 易误解 | 补充 `w=fill h=180` 等价写法 | 使用现有语法，不新增另一套尺寸语言 |
| 完整 box 导航是隐藏能力 | 增加 phone-shell.tabBar 自定义 box 范例 | 文档与独立导航范例 |
| 栖羽图片/手机底部圆角露边 | image.radius/opacity 烘入 Alpha；四个局部遮罩覆盖内屏外前景，遮罩自身也受机身边界限制 | 像素回归、原生生成、保存重开、真实浏览器图片 Alpha 和点击流程 |

### 本次验证

- 视觉定向回归：6/6。修复前同一命令出现 3 个断言失败和 1 个未知属性错误；修复后通过。
- RP/1 语言：50/50；已有创作质量：10/10；问题报告定向检查：69/69；真实 stdio MCP 检查：36/36；核心 Node 检查：17/17。
- 栖羽修复版：9 页、482 个顶层元件、2 个动态面板、4 个状态、4 个变量；原生结构 `unparseable/danglingRefs/problems=0`。
- 栖羽修复版在 Axure RP9 保存、关闭、重开成功。实际预览使用独立的新服务端口，先确认 4 个 screen-mask 元件，避免误测仍打开的旧版。
- 实际浏览器：26 项业务断言通过，包括收藏、填地点/备注、保存回显、计数更新、图鉴/详情切换和地点/识鸟流程。0 张断裂图片。
- 直接读取真实 Axure HTML 的图片像素：翠鸟图 Alpha 为 `[0,255,0]`（左上/中心/右下）；角部遮罩为 `[0,255,0]`（机身外/边缘/内屏）。确认透明圆角已进入宿主导出资源。
- 两页导航范例：80 个元件，结构三零，Axure RP9 保存关闭重开成功，3 项实际跨页导航断言通过。

结构、静态渲染、实际预览、保存重开分别记录；没有把本次测试写成 GUI 手工改稿证据。浏览器截图接口在部分后台页超时，不能把这些失败写为“截图已取得”；已保留静态预览、实际 DOM/像素检查和交互报告。
